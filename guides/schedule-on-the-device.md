# Schedule on the Device

<!-- AUTHOR: Skeleton, outline only (guide 6 of 6, capstone). Expand into full prose, verify uniot::Date availability at boot and time-zone handling, then remove `hidden: true` and add to SUMMARY.md after the custom primitive guide. -->

A lamp that switches on at 19:00 and off at 23:00, every day, whether or not the cloud is reachable. The device gets the time from Uniot Core, the schedule from two retained sliders, and an override switch from the dashboard. Everything from the previous guides comes together. About 40 minutes.

## What You'll Build

- A `minutes_now` primitive exposing minutes since midnight from Uniot Core's NTP-synced clock.
- An Emulator mock that fast-forwards a whole day in about a minute and a half.
- A schedule script that publishes `lamp` only on transitions.
- Dashboard sliders for the on and off times, and an override switch.
- A network cut across a scheduled transition, and a lamp that switches on time anyway.

Why it matters: this is a device acting as a smart agent with its own logic, not a board waiting for commands ([Edge Logic Deployment](../foundations/edge-logic-deployment.md)).

## Prerequisites

- The board from the previous guides. The LED on digital output `0` is the lamp; a relay module on the same output turns it into a real one. <!-- AUTHOR: relay wiring and a safety note if mains is mentioned; otherwise keep to low-voltage. -->

## Step 1: Expose the Time

{% code title="main.cpp (excerpt)" lineNumbers="true" %}

```c++
#include <Uniot.h>

using namespace uniot;

#define TZ_OFFSET_MINUTES 120  // AUTHOR: local offset from UTC; consider a build flag

// (minutes_now) -> minutes since local midnight, 0..1439
Object minutes_now(Root root, VarObject env, VarObject list) {
  auto expeditor = PrimitiveExpeditor::describe("minutes_now", Lisp::Int, 0)
                       .init(root, env, list);
  expeditor.assertDescribedArgs();

  time_t now = Date::now();
  int minutes = ((now / 60) + TZ_OFFSET_MINUTES) % 1440;
  return expeditor.makeInt(minutes);
}

void setup() {
  // ... everything from the previous guides ...
  Uniot.addLispPrimitive(minutes_now);
  Uniot.begin();
}
```

## Step 2: The Schedule Script

{% code title="schedule.lisp" lineNumbers="true" %}

```lisp
;;; begin-user-library
; (defjs minutes_now ()) ;-> Int
; (defjs dwrite (pin state)) ;-> Bool
;;; end-user-library

(define on_at 1140)   ; 19:00
(define off_at 1380)  ; 23:00
(define now 0)
(define active ())
(define last ())

(task 0 1000 '
 (list
  (setq now (minutes_now))
  (setq active (and (>= now on_at) (< now off_at)))
  (dwrite 0 active)
  (if (not (= active last))
   (list
    (setq last active)
    (push_event 'lamp active)))
  (if (is_event 'on_at)
   (setq on_at (pop_event 'on_at)))
  (if (is_event 'off_at)
   (setq off_at (pop_event 'off_at)))))
```

{% endcode %}

What the script does:

- Once a second it asks the time and computes whether the lamp should be on.
- Writes the output every pass, publishes `lamp` only when the state flips.
- Takes new on and off times from the dashboard.

In the Visual Editor: **task**, **set variable** from the autogenerated **minutes_now** block, **and** with two **comparisons**, **digital write**, **if** with **not** and **comparison**, **push event**, two **if** blocks with **is event** and **pop event**.

## Step 4: Cut the Network Across a Transition

- Deploy from the Emulator header. Set `on_at` a couple of minutes ahead of the real time.
- Switch the router off before that minute. The lamp turns on at the scheduled minute regardless.
- Bring the network back: the `lamp` event arrives, the LED widget updates, and the retained sliders are re-read.
